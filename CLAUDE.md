# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

FishScanner (fork of david-svitov/fishscanner): a desktop Python/OpenGL app that turns photos of hand-drawn fish into animated sprites in a virtual aquarium. Photos dropped into `photos/` are scanned (ArUco markers → perspective warp → background removal) and appear live without restarting.

## Commands

There are two entry points: `main_ocean.py` (console script `fishscanner`), the app in a glfw window, and `main_server.py` (`fishscanner-server`), the same scanning, roster and web server with no window, for a browser to draw the tank.

```bash
uv sync                    # creates .venv from pyproject.toml + uv.lock (Python >= 3.11)
uv run fishscanner         # runs the app (native glfw window, no X11)
uv run fishscanner-server  # runs the server alone (--port, default 8080); the tank page is at /tank/; Ctrl-C stops it
uv run pytest              # all tests; GL tests render into a hidden window and skip where none can be created;
                           # tests/tank/*.test.js run in the installed Google Chrome and skip without it
uv run ruff check . && uv run ruff format --check . && uv run pyright   # the CI gates (Ubuntu only; GL tests run locally)
```

Run everything with `PYTHONDONTWRITEBYTECODE=1` when mutating source during a test session: a same-length edit restored within one second can leave a stale `.pyc` in use.

To try the scanner without the GL window, `engine.photos.scan_photo_file(path, SimpleScanner())` runs the two-call pipeline (`scan` then `remove_background`) on an RGB frame; `photos/example_fish1.jpg` and `example_fish2.jpg` are valid inputs, and `tests/make_golden.py` shows the batch version. Everything else in `photos/` is gitignored.

## Git discipline

One commit per branch and per PR. Squash follow-up commits into the branch's single commit before handing it over, and never commit directly to main.

## Architecture

Three packages plus two scripts:

- `engine/` is a tiny generic sprite engine on OpenGL 3.3 core (glfw window, VAOs, GLSL 3.30, no fixed-function calls).
  - `engine/shaders.py`: one vertex header and one fragment shader shared by every sprite program. A sprite kind supplies only a GLSL `vec4 transform(vec3 p)` function (the fish tail beat and seaweed sway live in `ocean/`; `timer` is a slow per-sprite bounce, `params` four per-sprite numbers), and `compile_program()` returns a `ShaderProgram` with cached uniform locations. The fragment shader discards texels with alpha ≤ 0.1, which replaces the old alpha test.
  - `engine/matrices.py`: numpy model/orthographic matrices, tested without GL. Model = translate · rotate x · rotate y · rotate z · scale.
  - `Drawing` (`engine/drawing.py`): base sprite. A unit quad subdivided into a `grid_x × grid_y` triangle mesh (so vertex shaders can bend it); meshes are uploaded once per grid size and shared (`Drawing.release_meshes()` at shutdown). `render(projection, default_shader)` sets `model`, `projection`, `color` and the bouncing `timer` uniform. Subclasses override `animation()` and `get_child_sprites()`.
  - `Renderer` (`engine/renderer.py`): GL state, the ortho projection from the framebuffer aspect, the default program, and a two-pass render each frame: opaque sprites with depth writes, then sprites flagged `is_transparent` with depth writes off and drawn farthest-first so nearer ones paint over (larger z is nearer). `animate()` and `render()` both walk every sprite and its children (bubbles) via `all_sprites()`. Texture factories accept gray/BGR/BGRA files.
  - `SimpleScanner` (`engine/simplescanner.py`): detects the four ArUco `DICT_4X4_50` markers (ids 3/1/2/4 = TL/TR/BR/BL, hard-coded to match the PDFs in `ocean/patterns/`), warps the page to the rectangle of their outer corners, then `remove_background` resizes to 800×600 and builds a mask from ink strokes (adaptive threshold on a red-weighted grayscale of the RGB input) OR painted colour (HSV saturation more than `paint_saturation_margin` above the paper's, measured from the frame's blank border, and value above `paint_min_value`), keeps the largest contour as the alpha mask, and blanks 110px corner squares where the markers sit. Counting paint as drawing is what keeps a filled fin opaque when the crop cuts its outline. `scan` raises `ValueError` when markers are missing; callers catch it and skip the photo.
- `ocean/` is the aquarium scene built on the engine. `DrawingFish` is a state machine `init` → `swim` → `finish`: the entry (arrives at `ENTRY_SPEED`, decays by its water resistance toward a cruising speed chosen at entry, velocity carried into swimming unchanged), then swimming with a slow cosine *distance cycle* (`distance_cycle`, random 10-25 s period) that shrinks the fish to `FAR_SCALE`, slows it to `FAR_SPEED`, tints it to `FAR_TINT` and pushes it to `FAR_Z` before growing it back; facing lives in the sign of `_base_scale[0]`, never in the drawn `scale`. It never flips its velocity: `_steer` rotates the heading a bounded amount per tick, away from any border within `TURN_MARGIN_X` / `TURN_MARGIN_Y` (committing once to the way round that curves toward the band's middle), otherwise wandering gently and levelling; `_face_heading` turns the sprite about y to match the heading's x sign and `_pitch_to_heading` tips the nose about z toward the heading's climb or dive (`pitch_for_climb`: a 5 degree deadband so the cruise wander does not rock the fish, `MAX_PITCH` by 45 degrees, eased, sign flipped for a mirrored sprite). `go_away()` starts the exit (level, ramping to double speed, along the heading if it is at least 20% sideways, else the way the sprite faces) and `is_alive` flips when off-screen. Bubbles are `DrawingBubble` children that inherit the fish's distance. `FISH_TRANSFORM` is a side-view tail beat that foreshortens the tail in x and never moves y, driven by the fish's own beat phase and swing in `shader_params` (the `params` uniform), plus a gentle head turn (`params.z`) that foreshortens the head end by how fast the fish is changing depth (eased, so near zero at the near and far points, zero while held or leaving), which `animation()` advances from the fish's `tempo` and its current `effort` (rest/cruise/burst, re-chosen every few seconds and eased); speed is vector × distance factor × effort; `prevent_depth_crossings` (called from `step`) holds a fish's depth cycle only when its next step would meet or cross the depth of a fish whose painted rectangle (`extent` from the scan × the pitched footprint) it overlaps now or after this tick's move, so draw order never swaps mid-overlap while cycles otherwise continue (the more fish, the more waiting: measurements are in the plan's Part 11); `SEAWEED_TRANSFORM` sways the mesh with the slow `timer` bounce. Image assets live in `ocean/images/`, print templates in `ocean/patterns/`.
- `main_ocean.py` wires it together: `create_window()` opens the glfw window (3.3 core, forward-compatible, vsync); `main()` runs a fixed-step loop driven by `engine/clock.py`'s `FixedStepClock` (60 Hz `step()` ticks with a carried remainder and a 0.25 s stall cap, render every frame). Resizing calls `Renderer.resize`, which refits the viewport and projection so world units stay square; beyond `max_aspect` (the backgrounds' own 1.8:1) a wider window crops vertically rather than revealing space past the backgrounds.
  - **Scenes**: `Scene` owns the sprite list, the fish/seaweed programs and the background configs; `type: 'complex'` builds the full reef, `type: 'simple'` is one background image from `ocean.IMAGES_DIR` (package-relative, so the console script works from any directory). Left/Right arrows call `switch_background`, which drops every non-fish sprite and rebuilds. ESC closes the window.
  - **Fish lifecycle**: `engine/photos.py` owns photo discovery (`.jpg/.jpeg/.heic`, any case), decoding (both through PIL/pillow-heif with EXIF orientation applied; `None` on truncated or undecodable data, which OpenCV would silently decode partially) and scanning. At startup `load_fish_from_files` scans every photo already present; afterwards a `PhotoWatcher` daemon thread polls the folder and scans a new file only once its size has been stable for a settle time, retrying with backoff if the scan fails (stalled copy, truncated file, markers not found). Both push `(path, RGBA)` pairs onto `scanned_fish_queue`; the 60 Hz `step()` on the main thread drains all of it each tick, keeps every scan in `Scene.scans` by file name and registers it with the `FishRoster`, then calls `Scene.follow(roster.enabled())`, which sends away (`go_away()`) the fish no longer enabled and creates GL textures for enabled fish not yet in `Scene.swimming`, because GL calls must happen on the main thread. Disabled photos are scanned too, so re-enabling one is instant.
  - **Roster** (`ocean/roster.py`): `FishRoster` is the thread-safe record of which photos are fish, which are enabled (oldest first) and the cap (`FISH_LIMIT` is only the default; 1-30). Registering or enabling past the cap, or lowering it, disables the oldest enabled fish; raising it enables nothing. The cap and the disabled names persist in `photos/tank.json` (written atomically; unreadable means defaults with a printed warning); photos are never moved or deleted. It also holds each fish's thumbnail, a PNG cropped to the paint; its image, the whole scan as a quality-85 WebP (about 35 KB; libwebp keeps the alpha lossless, which a test checks on a real scan); and its `painted_extent`, which `snapshot()` lists with each fish.
  - **Remote control** (`remote/`): `create_app(roster, photos_dir)` is a FastAPI app serving `remote/index.html` (one plain HTML/JS page, no build step) and `/api/fish` (list), `PUT /api/fish/{name}` (`{"enabled": bool}`), `PUT /api/settings` (`{"cap": int}`), `/api/fish/{name}/thumbnail`, `/api/fish/{name}/image` (the WebP), the scene images under `/images/` (`ocean.IMAGES_DIR`), the tank page under `/tank/` (`remote/tank/`) and `POST /api/photos` (multipart field `photo`). An upload is staged as `<name>.upload` (a suffix the watcher ignores), scanned to reject photos without markers (422) and renamed into `photos/` under a generated `upload-<time>-<hex>` name, so the ordinary `PhotoWatcher` picks it up. `RemoteServer` binds the socket itself (so a busy port raises `OSError` in `main()`, which prints and carries on without the remote) and runs uvicorn on a daemon thread; the main thread stays the window's. `main()` prints `http://<lan_address()>:8080`.
  - **Standalone server** (`main_server.py`): owns `PHOTOS_DIR`, `STATE_FILE`, `SERVER_PORT`, `FISH_LIMIT` and `load_fish_from_files`, which `main_ocean.py` imports. Its `main()` runs the same startup scan, `PhotoWatcher` and `RemoteServer` with no window; a busy port exits with a one-line message (status 1), since without it there is nothing to serve. The main thread then registers each queued scan with the roster until Ctrl-C (`KeyboardInterrupt`), which stops the server and the watcher. `tests/test_main_server.py` runs it as a process on a free port.
  - **Tank page** (`remote/tank/`, served at `/tank/`): a line-for-line JavaScript port of `engine/` and `ocean/` onto WebGL 1, plain ES modules with no build step, written for Chromium 85 (a 2022 Samsung TV): ES2020 syntax at most, no APIs newer than Chromium 85 such as `.at()` or `Object.hasOwn`, no class fields, no top-level `await`, no CSS `inset`. The file layout mirrors the Python (`engine/drawing.js` is `engine/drawing.py`, `ocean/scene.js` is `main_ocean.Scene`) and names are camelCase. Differences from the Python: shaders are GLSL ES 1.00 only and every draw points the vertex inputs at its mesh (no VAOs); matrices are flat row-major arrays uploaded through `columnMajor()` (WebGL 1 only allows transpose `false`); meshes are cached per context in a `WeakMap`; `engine/random.js` is a seedable mulberry32 standing in for `numpy.random`; `mod()` and `copysign()` in `ocean/drawingfish.js` give Python's `%` and `math.copysign`, which the angle wrapping relies on (JavaScript's `%` keeps the dividend's sign). Decoration textures start as one transparent pixel and fill in when their image arrives, so `Scene` keeps the Python's synchronous shape. `fillTexture` sets `UNPACK_COLORSPACE_CONVERSION_WEBGL` to `NONE`: the decoration PNGs embed an Adobe RGB (1998) profile, which OpenCV ignores but Chrome would convert to sRGB (the open water's red drops from 26 to 0); with it the browser draws the desktop's scene to a mean difference of 0.35/255. `main.js`'s `Tank` polls `/api/fish` every 2 s (`enabled` oldest first), loads every fish's image into `scene.scans` (disabled ones too), and its `step()` is the Python `step()` minus the queue; `startTank()` sizes the canvas in CSS pixels, drives `frame()` from `requestAnimationFrame` through the same `FixedStepClock`, and returns `null` (the page shows a message) when there is no WebGL. The page sets `window.tank` for the console and the tests. A failed poll or image load is logged and retried on the next poll; anything else that throws surfaces as an unhandled rejection.
  - **Tank tests** (`tests/test_tank.py`): Playwright drives the installed Google Chrome (`channel="chrome"`, SwiftShader WebGL, so pixels match on any machine) against the real web app, which also mounts `tests/tank/` at `/tests/tank` for the run. Each `tests/tank/*.test.js` is one pytest case: `runner.html` imports it and `check.js` (a registry plus `assert`/`assertClose`, with numpy's `isclose` rule and defaults) returns its results. Every console message fails the test except ANGLE's read-pixels performance notice. `fish.test.js` ports every test in `test_fish.py`; Python's seed 0 enters from the left, which several of those rely on, so `fishTest` seeds a fish that does the same (`seedEntering`). `test_the_tank_page_...` loads `/tank/` with the example photos registered, follows a roster change, and checks a screenshot is not the clear colour. Use one WebGL context per test file: Chrome drops the oldest after about a dozen, with a console warning.
  - **Cleanup**: decoration textures are cached by file in `Scene` so switching scenes never allocates; every texture and program goes through the `Resources` registry (`resources.texture(...)` / `resources.program(...)`) so `main()` can delete them, release the shared meshes and `glfw.terminate()` on exit. A dead fish's texture is released when it is removed.

## Things that are stale or easy to get wrong

- Coordinate system is inverted on Y: `Renderer.resize` builds `orthographic(-half_width, half_width, half_height, -half_height, -1, 1)`, so smaller Y is higher on screen (fish `_top = -0.7`, `_bottom = 0.3`).
- The sprite list is only ever mutated on the main thread inside `step()` or a key callback; off-screen bubbles and dead fish are culled by rebuilding lists, never by removing during iteration.
- On macOS the application firewall blocks incoming LAN connections to uv's Python until it is allowed (see TROUBLESHOOTING.md), even from this machine to its own LAN address; loopback is unaffected, which is why the server tests use 127.0.0.1. A process listening on `127.0.0.1:<port>` (VS Code holds 8000 here) does not stop a `0.0.0.0` bind on macOS, it just shadows localhost.
- Bubbles are children of fish (`get_child_sprites()`); `Renderer.all_sprites()` flattens parents and children for both `animate()` and `render()`, so a sprite kind that is never drawn usually means it was not returned there.
