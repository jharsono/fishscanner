# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

FishScanner (fork of david-svitov/fishscanner) turns photos of hand-drawn fish into animated sprites in a virtual aquarium. A Python server scans the photos (ArUco markers → perspective warp → background removal) and serves a WebGL tank page that a browser draws, typically a TV's; photos dropped into `photos/` or uploaded from the phone remote appear live without restarting. The server needs no screen (a Raspberry Pi will do). The earlier desktop app, Python and OpenGL in a glfw window, is kept at the tag `desktop-final`, and its Raspberry Pi build at `desktop-pi`.

## Commands

The only entry point is `main_server.py` (console script `fishscanner`).

```bash
uv sync                    # creates .venv from pyproject.toml + uv.lock (Python >= 3.11)
uv run fishscanner         # runs the server (--port, default 8080): phone remote at /, tank page at /tank/; Ctrl-C stops it
uv run pytest              # all tests; tests/tank/*.test.js run in the installed Google Chrome and skip without it
uv run ruff check . && uv run ruff format --check . && uv run pyright   # the CI gates (Ubuntu, whose Chrome runs the tank tests)
```

Run everything with `PYTHONDONTWRITEBYTECODE=1` when mutating source during a test session: a same-length edit restored within one second can leave a stale `.pyc` in use.

To try the scanner on its own, `engine.photos.scan_photo_file(path, SimpleScanner())` runs the two-call pipeline (`scan` then `remove_background`) on an RGB frame; `photos/example_fish1.jpg` and `example_fish2.jpg` are valid inputs, and `tests/make_golden.py` shows the batch version. Everything else in `photos/` is gitignored.

## Git discipline

One commit per branch and per PR. Squash follow-up commits into the branch's single commit before handing it over, and never commit directly to main.

## Architecture

Two halves: the Python server (`engine/`, `ocean/`, `remote/`, `main_server.py`) and the tank page (`remote/tank/`, JavaScript), which the server serves.

### The server

- `SimpleScanner` (`engine/simplescanner.py`): detects the four ArUco `DICT_4X4_50` markers (ids 3/1/2/4 = TL/TR/BR/BL, hard-coded to match the PDFs in `ocean/patterns/`), warps the page to the rectangle of their outer corners, then `remove_background` resizes to 800×600 and builds a mask from ink strokes (adaptive threshold on a red-weighted grayscale of the RGB input) OR painted colour (HSV saturation more than `paint_saturation_margin` above the paper's, measured from the frame's blank border, and value above `paint_min_value`), keeps the largest contour as the alpha mask, and blanks 110px corner squares where the markers sit. Counting paint as drawing is what keeps a filled fin opaque when the crop cuts its outline. `scan` raises `ValueError` when markers are missing; callers catch it and skip the photo.
- **Photos** (`engine/photos.py`): photo discovery (`.jpg/.jpeg/.heic`, any case), decoding (both through PIL/pillow-heif with EXIF orientation applied; `None` on truncated or undecodable data, which OpenCV would silently decode partially) and scanning. At startup `load_fish_from_files` scans every photo already present; afterwards a `PhotoWatcher` daemon thread polls the folder and scans a new file only once its size has been stable for a settle time, retrying with backoff if the scan fails (stalled copy, truncated file, markers not found). Both push `(path, RGBA)` pairs onto `scanned_fish_queue`. Disabled photos are scanned too, so re-enabling one is instant.
- **Roster** (`ocean/roster.py`): `FishRoster` is the thread-safe record of which photos are fish, which are enabled (oldest first) and the cap (`FISH_LIMIT` is only the default; 1-30). Registering or enabling past the cap, or lowering it, disables the oldest enabled fish; raising it enables nothing. The cap and the disabled names persist in `photos/tank.json` (written atomically; unreadable means defaults with a printed warning); photos are never moved or deleted. It also holds each fish's thumbnail, a PNG cropped to the paint; its image, the whole scan as a quality-85 WebP (about 35 KB; libwebp keeps the alpha lossless, which a test checks on a real scan); and its `painted_extent`, which `snapshot()` lists with each fish. `ocean/` also holds the tank's images (`ocean/images/`, `ocean.IMAGES_DIR`) and the print templates (`ocean/patterns/`).
- **Web app** (`remote/`): `create_app(roster, photos_dir)` is a FastAPI app serving the phone remote `remote/index.html` (one plain HTML/JS page, no build step) and `/api/fish` (list), `PUT /api/fish/{name}` (`{"enabled": bool}`), `PUT /api/settings` (`{"cap": int}`), `/api/fish/{name}/thumbnail`, `/api/fish/{name}/image` (the WebP), the scene images under `/images/`, the tank page under `/tank/` (`remote/tank/`) and `POST /api/photos` (multipart field `photo`). An upload is staged as `<name>.upload` (a suffix the watcher ignores), scanned to reject photos without markers (422) and renamed into `photos/` under a generated `upload-<time>-<hex>` name, so the ordinary `PhotoWatcher` picks it up. `RemoteServer` binds the socket itself (so a busy port raises `OSError` where the caller can see it) and runs uvicorn on a daemon thread.
- **`main_server.py`** owns `PHOTOS_DIR`, `STATE_FILE`, `SERVER_PORT` and `FISH_LIMIT`. Its `main()` runs the startup scan, starts the `PhotoWatcher` and the `RemoteServer` (a busy port exits with a one-line message, status 1), prints the remote's and the tank's addresses from `lan_address()`, then registers each queued scan with the roster on the main thread until Ctrl-C (`KeyboardInterrupt`), which stops the server and the watcher. `tests/test_main_server.py` runs it as a process on a free port.

### The tank page (`remote/tank/`, served at `/tank/`)

Plain ES modules with no build step, ported line for line from the desktop app's Python (tag `desktop-final`), whose layout it keeps: `engine/` is the sprite engine, `ocean/` the aquarium; names are camelCase. It is written for Chromium 85 (a 2022 Samsung TV): ES2020 syntax at most, no APIs newer than Chromium 85 such as `.at()` or `Object.hasOwn`, no class fields, no top-level `await`, no CSS `inset`.

- `engine/shaders.js`: one vertex header and one fragment shader (GLSL ES 1.00, WebGL 1's language) shared by every sprite program, with the vertex inputs bound to `POSITION_ATTRIBUTE`/`TEXCOORD_ATTRIBUTE` before linking. A sprite kind supplies only a GLSL `vec4 transform(vec3 p)` function (the fish tail beat and seaweed sway live in `ocean/`; `timer` is a slow per-sprite bounce, `params` four per-sprite numbers), and `compileProgram(gl, transform)` returns the program with its uniform locations (null for one the transform does not use). The fragment shader discards texels with alpha ≤ 0.1.
- `engine/matrices.js`: flat row-major 4×4 arrays (`row * 4 + col`); model = translate · rotate x · rotate y · rotate z · scale. `columnMajor()` lays one out for `uniformMatrix4fv`, whose transpose argument WebGL 1 only allows to be `false`.
- `Drawing` (`engine/drawing.js`): base sprite, a unit quad subdivided into a `gridX × gridY` triangle mesh (so vertex shaders can bend it). Meshes are uploaded once per grid size and cached per context in a `WeakMap`; WebGL 1 has no vertex array objects, so every draw points the vertex inputs at its mesh. `render(gl, projection, defaultShader)` sets `model`, `projection`, `color`, `params` and the bouncing `timer`. Subclasses override `animation()` and `getChildSprites()`.
- `Renderer` (`engine/renderer.js`): GL state, the ortho projection from the drawing buffer's aspect, the default program, and a two-pass render each frame: opaque sprites with depth writes, then sprites flagged `isTransparent` with depth writes off and drawn farthest-first so nearer ones paint over (larger z is nearer; the sort is stable, so at equal depth the earlier sprite ends on top). Beyond `maxAspect` (the backgrounds' own 1.8:1) a wider window crops vertically rather than revealing space past the backgrounds. `CONTEXT_ATTRIBUTES` asks for an opaque, unantialiased context. `createTexture`/`fillTexture` upload any `TexImageSource` clamped and without mipmaps (what WebGL 1 allows for sizes that are not powers of two), with `UNPACK_COLORSPACE_CONVERSION_WEBGL` set to `NONE`: the decoration PNGs embed an Adobe RGB (1998) profile, which the desktop app (OpenCV) ignored but Chrome would convert to sRGB (the open water's red drops from 26 to 0). `loadImage(url)` decodes an image.
- `engine/clock.js`: `FixedStepClock`, 60 Hz ticks with a carried remainder and a 0.25 s stall cap. `engine/random.js`: a seedable mulberry32 with numpy's shapes (`uniform`, `randint`, `choice`).
- `ocean/drawingfish.js`: `DrawingFish` is a state machine `init` → `swim` → `finish`: the entry (arrives at `ENTRY_SPEED`, decays by its water resistance toward a cruising speed chosen at entry, velocity carried into swimming unchanged), then swimming with a slow cosine *distance cycle* (`distanceCycle`, random 10-25 s period) that shrinks the fish to `FAR_SCALE`, slows it to `FAR_SPEED`, tints it to `FAR_TINT` and pushes it to `FAR_Z` before growing it back; facing lives in the sign of `_baseScale[0]`, never in the drawn `scale`. It never flips its velocity: `_steer` rotates the heading a bounded amount per tick, away from any border within `TURN_MARGIN_X` / `TURN_MARGIN_Y` (committing once to the way round that curves toward the band's middle), otherwise wandering gently and levelling; `_faceHeading` turns the sprite about y to match the heading's x sign and `_pitchToHeading` tips the nose about z toward the heading's climb or dive (`pitchForClimb`: a 5 degree deadband so the cruise wander does not rock the fish, `MAX_PITCH` by 45 degrees, eased, sign flipped for a mirrored sprite). `goAway()` starts the exit (level, ramping to double speed, along the heading if it is at least 20% sideways, else the way the sprite faces) and `isAlive` flips when off-screen. Bubbles are `DrawingBubble` children that inherit the fish's distance. `FISH_TRANSFORM` is a side-view tail beat that foreshortens the tail in x and never moves y, driven by the fish's own beat phase and swing in `shaderParams` (the `params` uniform), plus a gentle head turn (`params.z`) that foreshortens the head end by how fast the fish is changing depth (eased, so near zero at the near and far points, zero while held or leaving), which `animation()` advances from the fish's `tempo` and its current `effort` (rest/cruise/burst, re-chosen every few seconds and eased); speed is vector × distance factor × effort. `preventDepthCrossings` (called from `Tank.step`) holds a fish's depth cycle only when its next step would meet or cross the depth of a fish whose painted rectangle (`extent` from the server × the pitched footprint) it overlaps now or after this tick's move, so draw order never swaps mid-overlap while cycles otherwise continue (the more fish, the more waiting: measurements are in MODERNIZATION_PLAN.md's Part 11). `mod()` and `copysign()` give Python's `%` and `math.copysign`, which the angle wrapping relies on. `SEAWEED_TRANSFORM` (`ocean/drawingseaweed.js`) sways the mesh with the slow `timer` bounce.
- `Scene` (`ocean/scene.js`): the sprite list, the fish/seaweed programs and the background configs; `type: 'complex'` builds the full reef, `type: 'simple'` is one background image from `/images/`. Decoration textures are cached by file name, so switching scenes never allocates, and start as one transparent pixel that fills in when the image arrives. `switchBackground` drops every non-fish sprite and rebuilds. `scans` maps photo names to `{image, extent}`; `follow(enabled)` sends away (`goAway()`) the fish no longer enabled and adds enabled fish whose image has arrived; `removeDeadFish` deletes a dead fish's texture.
- `main.js`: `Tank` polls `/api/fish` (`poll()`, every 2 s; `enabled` oldest first) and loads every fish's image into `scene.scans`, disabled ones too; `step()` runs `preventDepthCrossings`, `animate`, `follow` and `removeDeadFish`; `frame(seconds)` runs the ticks due and renders. `startTank()` sizes the canvas in CSS pixels (a TV's GPU fills 1080p far more easily than 4K), refits on resize, maps Left/Right to `switchBackground` and a click or F to fullscreen, keeps polling and drives `frame()` from `requestAnimationFrame`; it returns `null` when there is no WebGL, and the page then shows a message. The page sets `window.tank` for the console and the tests. A failed poll or image load is logged and retried on the next poll; anything else that throws surfaces as an unhandled rejection.
- **Tank tests** (`tests/test_tank.py`): Playwright drives the installed Google Chrome (`channel="chrome"`, SwiftShader WebGL, so pixels match on any machine) against the real web app, which also mounts `tests/tank/` at `/tests/tank` for the run. Each `tests/tank/*.test.js` is one pytest case: `runner.html` imports it and `check.js` (a registry plus `assert`/`assertClose`, with numpy's `isclose` rule and defaults) returns its results. Every console message fails the test except ANGLE's read-pixels performance notice. The fish, renderer, scene, matrix and clock tests were ported from the Python ones (tag `desktop-final`); `test_the_tank_page_...` loads `/tank/` with the example photos registered, follows a roster change, and checks a screenshot is not the clear colour.

## Things that are stale or easy to get wrong

- Coordinate system is inverted on Y: `Renderer.resize` builds `orthographic(-halfWidth, halfWidth, halfHeight, -halfHeight, -1, 1)`, so smaller Y is higher on screen (fish `_top = -0.7`, `_bottom = 0.3`).
- The sprite list is only ever changed inside `Tank.step()` or a key handler; off-screen bubbles and dead fish are culled by rebuilding arrays, never by removing during iteration.
- Bubbles are children of fish (`getChildSprites()`); `Renderer.allSprites()` flattens parents and children for both `animate()` and `render()`, so a sprite kind that is never drawn usually means it was not returned there.
- JavaScript's `%` keeps the dividend's sign; use `mod()` wherever an angle or index wraps. A loop bound that the loop body changes (`_initAnimationStep` counts down during the entry) must be read into a variable first, unlike Python's `range()`.
- Several fish tests rely on a fish that enters from the left and so faces right (as numpy's seed 0 did); `fishTest` seeds one (`seedEntering`). Use one WebGL context per test file: Chrome drops the oldest after about a dozen, with a console warning.
- On macOS the application firewall blocks incoming LAN connections to uv's Python until it is allowed (see TROUBLESHOOTING.md), even from this machine to its own LAN address, so a phone or TV cannot connect until then; loopback is unaffected, which is why the server tests use 127.0.0.1. A process listening on `127.0.0.1:<port>` (VS Code holds 8000 here) does not stop a `0.0.0.0` bind on macOS, it just shadows localhost.
